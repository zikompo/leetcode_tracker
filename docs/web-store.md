# Chrome Web Store listing

Everything needed to publish LeetTrack. Uploading needs your own Chrome Web Store developer account (a one-time registration fee), so that step is yours.

## 1. Build the package

```bash
pnpm --filter @leettrack/extension zip:store
```

This writes `apps/extension/.output/leettrack-<version>-chrome.zip`. It is built **without** the manifest `key`: the store doesn't accept one on a new item, and it assigns the item its own key.

Build it with your production settings in `apps/extension/.env.local`:

- `WXT_WEBSITE_URL`: the deployed website, e.g. `https://leettrack.vercel.app`;
- `WXT_SUPABASE_URL` and `WXT_SUPABASE_ANON_KEY`;
- `WXT_GITHUB_CLIENT_ID` and `WXT_GITHUB_APP_SLUG`, if you use GitHub sync.

## 2. Keep one extension ID after the first upload

1. Upload the zip as a draft (you don't have to publish yet).
2. On the item's **Package** tab, open **View public key** and copy the text between the `BEGIN` and `END PUBLIC KEY` lines, without the newlines.
3. Put it in `apps/extension/.env.local` as `WXT_EXTENSION_KEY=...`.
4. Rebuild with `pnpm --filter @leettrack/extension build` and reload the unpacked extension. Its ID now matches the store item's.
5. Add that ID to the website's `NEXT_PUBLIC_EXTENSION_IDS`, comma-separated after the development ID `bpjaccjmefnfblponnmbnpkdmiegpcfo`.

Until then, unpacked builds use the development key in `apps/extension/key.pub.txt`. Its private half is in `.local/extension-key.pem`, which is never committed; the store doesn't need it.

## 3. Listing text

**Name:** LeetTrack

**Summary** (132 characters at most):

> Log every LeetCode attempt in one tap, review problems right before you'd forget them, and see which patterns you can spot cold.

**Category:** Education

**Language:** English

**Description:**

> LeetTrack keeps a record of your LeetCode practice and tells you what to do next.
>
> - One-tap logging: after an Accepted, a small panel (or Chrome's side panel) has the outcome, time, complexity and patterns filled in. Change anything, or just save.
> - Spaced repetition: reviews are scheduled with FSRS, so problems come back just before you'd forget them. The toolbar badge shows what's due today.
> - Patterns, not just problems: see how well you know each pattern, including how often you spot it on a first try, and which ones you can re-solve but miss cold.
> - Interview mode: set an interview date and LeetTrack plans the problems left on your lists, brings shaky ones back for a review just before, and keeps the last days for review only.
> - Timebox: past your time limit, it suggests one hint at a time instead of the solution.
> - Works on NeetCode too: turn it on in Settings, and attempts on neetcode.io count toward the same problems.
> - Optional: sync to the companion website, commit Accepted solutions to your GitHub repo, and get complexity suggestions from an AI provider you choose.
>
> Works offline with no account. LeetTrack never stores problem statements.

## 5. Privacy practices tab

**Single purpose:** Track your LeetCode practice: log attempts, schedule reviews and show progress by pattern.

**Permission justifications:**

| Permission                                  | Why                                                                                                                                               |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `storage`                                   | Keeps your attempts, settings and the sign-in session in the browser.                                                                             |
| `alarms`                                    | Updates the due-today badge at midnight and hourly, and syncs or retries GitHub commits in the background.                                        |
| `sidePanel`                                 | Lets the log panel live in Chrome's side panel if you choose that.                                                                                |
| Host access to `https://leetcode.com/*`     | Shows the log panel on problem pages and notices your submissions' results.                                                                       |
| Optional hosts (`https://*/*`, `localhost`) | Asked for one origin at a time, only when you turn on NeetCode or set up an AI provider or GitHub sync, so the extension can reach that one site. |
| `scripting`                                 | Adds the log panel to neetcode.io problem pages, only after you turn NeetCode on in Settings and allow access to neetcode.io.                     |
| `identity`                                  | Opens GitHub sign-in in a Chrome window and brings you back to the extension, so you can sync with the website.                                   |

**Remote code:** No. All code is in the package.

**Data usage** (tick these):

- _Personally identifiable information_: yes, only if you sign in (GitHub username and email, from GitHub sign-in).
- _Authentication information_: yes (the sign-in session and GitHub token, kept in the browser).
- _Website content_: yes (your solutions' code and results on leetcode.com).
- _User activity_: yes (when you attempt problems and how long they take).

Then certify:

- the data isn't sold;
- it isn't used for purposes unrelated to the single purpose;
- it isn't used for creditworthiness or lending.

**Privacy policy URL:** `https://<your-website>/privacy`
